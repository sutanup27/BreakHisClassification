User guide

BreaKHis classification and pruning

This project trains PyTorch models to classify breast histology images as benign or malignant, then evaluates, prunes, and fine-tunes the saved models. Model commands support binary classification. The eight-subtype dataset is audited, but multiclass training is not implemented yet.

Recommended workflow: run and compare experiments. Use one saved config per experiment to train, evaluate and compare saved results.

powershell
# Activate your installed environment first; prepare the split only if missing.

User guide

Complete binary workflow

These commands use the existing saved manifest and the remaining v1 binary dataset. Keep the manifest, source, and magnification consistent throughout the experiment.

powershell
# Train and select the best weights using validation accuracy.
python -m breakhis train --dataset breakhis --source cancer_binary --magnification 40X --model vgg --epochs 20 --device auto --experiment-id baseline

# Prune weights and check validation performance.
python -m breakhis prune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --sparsity 0.5 --experiment-id baseline

# Fine-tune with the pruning masks still active.
python -m breakhis finetune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/prune.pth --epochs 5 --learning-rate 0.0001 --experiment-id baseline

# Evaluate the selected model on the reserved test split.
python -m breakhis evaluate --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/finetune.pth --output artifacts/final-test.json

Training and fine-tuning use the training split and choose weights using validation accuracy. Pruning reports validation performance. Evaluation uses the reserved test split; run it after choosing your model and pruning settings. Reported accuracy is a percentage on a 0-100 scale: 90.0 means 90%.

User guide

Train parameters

python -m breakhis train creates a new model unless --resume is supplied.

ParameterDefault / allowed valuesPurpose
--modelvgg; vgg, resnet, resnet18Architecture. resnet is an alias for torchvision ResNet18. The chosen name is used in the default checkpoint directory.
--epochs20; positive integerPasses through the training split. Validation runs after every epoch.
--learning-rate0.001Initial SGD learning rate. Use a positive value; for example 0.0001 for smaller updates.
--pretrainedOff; flagLoads torchvision pretrained ResNet18 weights, potentially downloading them. The binary classifier head is replaced. Has no effect for VGG, which does not load pretrained weights.

SGD uses momentum 0.9, weight decay 0.0005, and cosine learning-rate scheduling over the requested epochs. These settings are currently fixed in code. Weights are saved when validation accuracy improves. A new run refuses an existing checkpoint output. Choose a new experiment ID or output filename.

powershell
python -m breakhis train --dataset breakhis --model resnet18 --pretrained --epochs 10 --batch-size 16 --output resnet18-baseline.pth

This custom filename saves to ../checkpoint/binary/resnet18-baseline.pth.

User guide

Prune parameters

python -m breakhis prune loads weights, applies masks, checks validation, and saves weights. It performs no training.

ParameterDefault / allowed valuesPurpose
--checkpointRequired; file pathSupported checkpoint to prune. Architecture is reconstructed automatically.
--sparsity0.5; number from 0 to 1 inclusiveFraction selected for L1 unstructured pruning in each convolution and linear layer. 0.5 requests 50%; 0 requests none; 1 selects all. This does not remove channels or guarantee faster inference.
--methodunstructured; unstructured, channelWeight masks for VGG/ResNet18, or physical VGG channel removal. Channel ratios must be below 1; residual/depthwise channel models are unsupported.
--layer-sparsitiesNone; JSON file pathComplete layer-name-to-ratio map. Replaces the uniform ratio; missing/unknown names fail. See pruning details for names and a template.

Masks are stored in the checkpoint and reconstructed on loading. Dense tensor shapes remain unchanged.

With --method channel, VGG convolution widths, batch normalization, downstream inputs, and classifier columns are rebuilt together. Channel configuration is saved for automatic loading and fine-tuning. At least one channel remains per layer. Mixing channel-pruned models with unstructured masks is rejected.

powershell
python -m breakhis prune --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --method channel --sparsity 0.5 --experiment-id channel-50
python -m breakhis finetune --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/channel-50/prune.pth --epochs 5 --experiment-id channel-50

Each pruning run writes prune.validation.json beside its checkpoint. Choose ratios using validation results, then reserve test evaluation for the selected model. Unstructured masks, original masked weights, and matching optimizer buffers remain zero through fine-tuning. Re-pruning targets total mask sparsity; decreasing existing sparsity is rejected. Magnitude ties are resolved deterministically. See PRUNING.md for full rules.

Fine-tune parameters

python -m breakhis finetune starts a new optimization run from saved weights. Pruned checkpoints retain their masks.

ParameterDefault / allowed valuesPurpose
--checkpointRequired for a new run; replaced by --resume when continuingStarting weights; architecture is read from the checkpoint. Do not supply --model.
--epochs20; positive integerAdditional training epochs. Set explicitly, for example --epochs 5.
--learning-rate0.001Initial rate for the new SGD optimizer. A smaller value can be useful for fine-tuning.

Uses the same optimizer, scheduler, and validation selection as training. Without --resume, optimizer, scheduler, and RNG state start a new run. With --resume, their saved states are restored.

Evaluate parameters

python -m breakhis evaluate evaluates saved weights on the test split.

ParameterDefault / allowed valuesPurpose
--checkpointRequired; file pathModel weights; architecture and pruning masks are reconstructed.
--outputExperiment-directory evaluate.jsonJSON report path. Example: --output artifacts/final-test.json. Parent folders are created. Evaluation saves no model weights.

The JSON report is printed and saved even without --output. It now includes image and filename patient/slide metrics, size accounting, Conv2d/Linear MAC/FLOP estimates, and measured forward latency. Class labels, averaging conventions, metric units, checkpoint hashes, and hardware/runtime details are explicit. Accuracy is 0-100%; precision, recall, F1, sensitivity and specificity are 0-1. Patient/slide results average image probabilities by filename ID, not verified clinical identity. See evaluation definitions.

Compare dense, pruned, and fine-tuned models

After choosing models with validation, compare them on the same reserved test split and benchmark protocol:

powershell
python -m breakhis compare --dataset breakhis --dense ../checkpoint/binary/40X/vgg/baseline/train.pth --pruned ../checkpoint/binary/40X/vgg/baseline/prune.pth --finetuned ../checkpoint/binary/40X/vgg/baseline/finetune.pth --device auto --cpu-threads 2 --benchmark-batch-size 1 --benchmark-warmup 10 --benchmark-repeats 30 --output artifacts/comparison.json

Supply the original manifest/source/magnification on each command if different from defaults. For channel pruning, point the last two inputs to its channel experiment. All inputs must share data provenance and architecture; pruned/fine- tuned masks or channel topology must match. File roles are operator-supplied; the comparison does not independently establish training history.

ParameterDefault / accepted valuesPurpose
--denseRequired for compareDense baseline checkpoint path
--prunedRequired for comparePruned-before-fine-tuning checkpoint path
--finetunedRequired for compareSelected fine-tuned checkpoint path
--benchmark-batch-size1; positive integerResident forward benchmark batch; independent of evaluation --batch-size
--benchmark-warmup10; nonnegative integerUntimed forwards, after one untimed MAC-counting forward
--benchmark-repeats30; positive integerTimed forward repeats; all samples are retained
--cpu-threadsUnchanged when omitted; positive integerFix PyTorch intra-op CPU threads; actual thread counts are recorded

The four benchmark options apply to both evaluate and compare. Comparison uses --dense/--pruned/--finetuned, not --checkpoint. Default report locations are ../checkpoint/binary/<magnification>/<architecture>/<experiment-id>/compare.json and evaluate.json, with sibling .config.json records. Custom report outputs must end in .json and cannot replace input checkpoints.

Reports distinguish actual checkpoint bytes, measured model-state serialization, dense parameter bytes, effective nonzeros, and theoretical sparse-value/index estimates. MAC counts cover Conv2d/Linear at actual input dimensions, excluding BN/activation/pooling/residual-add/mask operations; the FLOP estimate uses two FLOPs per MAC. Masked zeros do not reduce dense MACs.

Latency uses resident copies of a real preprocessed image and GPU synchronization around each forward. Disk IO, preprocessing, transfers and metrics are excluded. Median speedup below 1 means slower; the report retains slowdowns and larger files. Use the same hardware, shapes, dtype, threads, and warm-up/repeats when comparing. Full definitions and limitations are in EVALUATION.md.

Checkpoint paths and loading rules

CommandDefault output relative to the workspace parent
traincheckpoint/binary/<magnification>/<architecture>/<experiment-id>/train.pth
prunecheckpoint/binary/<magnification>/<architecture>/<experiment-id>/prune.pth
finetunecheckpoint/binary/<magnification>/<architecture>/<experiment-id>/finetune.pth

Defaults are resolved using the codebase location, independently of your working directory. For checkpoint commands, a bare output filename such as --output baseline.pth goes directly into checkpoint/binary/. An explicit relative or absolute path must resolve inside that task directory and end in .pth. From the codebase, --output ../checkpoint/binary/40X/vgg/baseline.pth is valid. Binary outputs cannot go into the multiclass directory. Checkpoint input paths can be anywhere.

Other explicit relative paths, including checkpoint inputs and evaluation reports, are relative to your current working directory. Quote paths containing spaces.

Each completed training/fine-tuning epoch also saves <name>-last.pth, including optimizer, scheduler, and random state. The main checkpoint remains the best validation model. Each command saves its resolved arguments as <name>.config.json; evaluation saves a JSON report automatically when no output is supplied.

Ctrl+C attempts to save partial-epoch weights as <name>-interrupted.pth. Resume from the completed-epoch -last.pth, not the partial weights. Work from an interrupted epoch is replayed. A second interruption or stalled operation can prevent saving.

Resume training and fine-tuning

ParameterCommandsPurpose
--resumetrain, finetuneCompleted-epoch checkpoint containing optimizer, scheduler, and RNG state. Cannot be combined with --checkpoint; training cannot combine it with --pretrained.
powershell
python -m breakhis train --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/train-last.pth
python -m breakhis finetune --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/finetune-last.pth

Omitted options inherit saved settings. --epochs is the original total planned epochs, not additional epochs on resume. Changing the planned total changes the cosine schedule and is rejected. Batch size, learning rate, worker count, deterministic mode, device, output, runtime versions, experiment ID, and dataset provenance must match. A fully completed run cannot be resumed for extra epochs; start finetune --checkpoint ... instead.

Exact epoch-boundary resume requires --num-workers 0. Background-worker RNG/prefetch states are not stored. The full original experiment directory, including its best checkpoint, must remain available. Reproducibility across different software/hardware or nondeterministic GPU operations is not guaranteed. Version-1 weights remain loadable for evaluation/pruning/fine-tuning, but do not contain exact resume state. See checkpoint format and resume.

Supported checkpoints contain architecture, binary labels, state dictionaries, epoch, and dataset metadata. Loading requires matching manifest hash, source, magnification, and preprocessing. Regenerating a manifest may invalidate checkpoint metadata. Old whole-model pickle files require explicit migration and are not automatically loaded.

prepare-data decodes and hashes images, checks folder/filename labels, links duplicate content, and saves approximately 70%/15%/15% patient-group splits for train/validation/test. Group fractions do not guarantee identical image fractions. See dataset details for the grouping policy.

User guide

Preprocessing and runtime

Images are converted to RGB and resized to a 256-pixel short edge with aspect ratio preserved. Training uses random 224 x 224 crops (padding 4) and horizontal flips. Validation/test use center crops. Tensors use ImageNet mean/std normalization. These are fixed in code; there is no image-size option. Older 460 x 700 evaluation accuracy is not directly comparable.

Each loaded image is checked against its manifest hash. Epoch logs show training and validation time, losses, and validation accuracy. --epochs 1 checks execution but still processes all selected images; there is no quick-subset argument. CPU execution and --magnification all can take longer. Measure throughput before increasing workers. Unstructured pruning does not automatically speed up dense computation.

Training and validation losses are averaged over samples, so a smaller final batch does not receive the same weight as a full batch. Invalid learning rates, epoch counts, and empty splits are rejected. Nonfinite inputs, outputs, losses, or gradient norms stop training; invalid gradients are rejected before the optimizer updates weights. This fail-fast validation can add device checks per batch.

Minimal evaluation protocol

  • Use one saved group-separated train/validation/test split for the first study.
  • Training uses only train; checkpoint choice uses validation. Default criterion: group balanced accuracy, ties by lower validation loss and then earlier epoch.
  • Primary group probability averages within each available magnification, then averages the magnification means equally. Report image-weighted grouping and image metrics secondarily. Group identity comes from filenames.
  • The fixed binary operating point is argmax (0.5 reference; ties to benign). Separate threshold calibration, constrained candidate search and nested cross-validation are not part of this minimal runner.
  • Preprocessing uses the existing aspect-preserving resize-256/crop-224 and ImageNet normalization. Training adds random crop and horizontal flip; all evaluation preprocessing is deterministic. This deliberately reuses tested code rather than adding another transform pipeline.
  • Example training is Adam, learning rate 0.0001, weight decay 0.0001, no scheduler. Full parameters are in the config reference.
  • CPU resident-forward latency is primary; a config can instead select GPU. Timing is one session per evaluation; repeat sessions before performance claims.

These implemented settings supersede conflicting earlier pilot defaults for the simple workflow. Prior dataset use is acknowledged; results are held-out within this study, without historical-untouched or verified-patient claims. Literature review proceeds alongside the experiments and supports later claims.

Dataset policy

Identifier rule

The official BreaKHis dataset description documents procedure, tumor class, subtype, year, slide identifier, magnification, and sequence in the image filename. The grouping rule uses the full YEAR-SLIDE_ID:

text
SOB_B_A-14-22549AB-40-001.png
        └─ 14-22549AB is the patient/slide group

The subtype, magnification, and image sequence are excluded from the group key. Letter suffixes are preserved. The same identifier is grouped together even when it appears under more than one subtype. Local filenames yield 81 patient/slide groups; this is the local filename census, not an independently verified count of distinct people. No external patient-to-slide metadata is present in the repo.

Exact decoded-image duplicates also link groups before splitting, so matching content cannot appear in different splits. Conflicting binary labels within linked groups fail the audit rather than silently choosing a label.

Dataset policy

Split policy

The saved seed defaults to zero. Groups are stratified by binary label, shuffled with a local seeded generator, and allocated approximately 70% training, 15% validation, and 15% test by group count. Image proportions differ because patients have different numbers of images. Class/image distributions are reported for each source, magnification, and split.

All magnifications and all local source copies use consistent assignments for a patient/slide identifier. --magnification all therefore preserves group isolation. The audit validates zero patient overlap and zero exact decoded-content overlap across splits. It does not establish that visually similar, nonidentical images are unrelated; the filename identifier remains the patient-group reference.

Checkpoints & resume

Resume semantics

powershell
python -m breakhis train --dataset breakhis --experiment-id baseline --epochs 20 --num-workers 0 --deterministic
# If interrupted before the planned run completes:
python -m breakhis train --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/train-last.pth

Resume uses the same command (train or finetune) as the saved run. Omitted options inherit the saved effective settings. The scheduler is stepped before each completed-epoch checkpoint is saved. Restore starts at epoch + 1, with optimizer momentum, learning-rate schedule, best-validation tracking, Python RNG, NumPy RNG, PyTorch CPU RNG, CUDA RNGs, and recorded backend determinism settings. An epoch-zero last checkpoint allows restarting if the first epoch is interrupted.

The original planned epoch count and learning rate, batch size, worker count, deterministic mode, resolved device, output path, experiment ID, runtime versions, and dataset provenance must match. A changed total would define a different cosine schedule and is rejected. Completed runs require a new fine-tuning run rather than extending resume. Restore the original best checkpoint if it was moved; the experiment's best and last files belong together.

Exact resume is supported at completed-epoch boundaries with num-workers 0. Positive-worker runs still save optimizer/scheduler information but are marked nonresumable because worker RNGs and prefetch queues are not captured. Partial interrupted weights are nonresumable; restart from the last completed epoch and replay the partial work. Software/hardware changes and nondeterministic GPU kernels can change numerical results even when random states are restored.

Checkpoints & resume

Verification

Regression tests compare an uninterrupted stochastic CPU run with interrupted and resumed runs, for both dense and masked models. Final weights, optimizer, scheduler, and RNG states must match exactly. Separate actual VGG subprocess checks compare dense and pruned predictions using atol=1e-6, rtol=1e-5. GPU smoke checks validate actual checkpoint loading and finite inference; they do not establish full-dataset model quality or cross-device numerical equivalence.

Pruning & fine-tuning

Channel-pruning workflow

Starting from a supported dense VGG with the same manifest/source/magnification:

powershell
python -m breakhis prune --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --method channel --sparsity 0.5 --experiment-id channel-50
python -m breakhis finetune --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/channel-50/prune.pth --epochs 5 --learning-rate 0.0001 --experiment-id channel-50
python -m breakhis evaluate --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/channel-50/finetune.pth --experiment-id channel-50

For nondefault data settings, supply the same manifest/source/magnification on every command. The narrower model is reconstructed from saved channel widths automatically.

Importance is the sum of absolute filter weights. Keep the highest-scoring outputs, with stable original-index ordering for ties. Copy corresponding batch-normalization affine values, running means/variances, and batch counters. Select the same indices in downstream convolution inputs and final classifier columns. RGB inputs and class labels remain unchanged. Channel pruning returns a new model without modifying the source.

The kept count is max(1, original - round(original * ratio)). Small layers may retain more than the nominal fraction. Zero-ratio channel pruning preserves predictions within numerical tolerance.

Pruning & fine-tuning

Per-layer settings

Optional --layer-sparsities layers.json replaces the uniform --sparsity with a complete JSON layer-name-to-ratio object. Specify every eligible layer exactly. Missing/unknown names, invalid ratios, NaN/infinity, and tied weights fail before any layer changes.

VGG channel settings require backbone.conv0 through backbone.conv7. VGG unstructured settings also require fc2. ResNet18 unstructured settings require all named Conv2d/Linear modules, including downsample convolutions and fc. Generate a complete unstructured template from the actual checkpoint:

python
import json
from pathlib import Path
from torch import nn
from breakhis.checkpoints import load_checkpoint

model, _ = load_checkpoint('../checkpoint/binary/40X/vgg/baseline/train.pth')
settings = {name: 0.5 for name, module in model.named_modules()
            if isinstance(module, (nn.Conv2d, nn.Linear))}
Path('layers.json').write_text(json.dumps(settings, indent=2), encoding='utf-8')

For channel settings, filter only nn.Conv2d and start from unmasked VGG. Edit values and run:

powershell
python -m breakhis prune --dataset breakhis --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --method unstructured --layer-sparsities layers.json --experiment-id layer-settings

The resolved map is saved in configuration and the validation report. The uniform ratio is still validated. JSON may use UTF-8 with or without a byte-order mark.

Pruning & fine-tuning

Mask invariants and edge cases

Unstructured pruning selects exactly round(numel * ratio) mask entries per layer. Stable sorting handles magnitude ties, one-element tensors, and zero-count rounding. Naturally zero weights can make numerical sparsity exceed mask sparsity. Empty tensors and shared weight storage are rejected.

Re-pruning targets the requested total mask fraction rather than pruning another fraction of remaining weights. Lowering existing sparsity is rejected; use dense weights to compare smaller ratios.

Training enforces masks before batches and after optimizer steps. Masked original weights and matching optimizer buffers, including SGD momentum, stay zero. Forward hooks retain differentiable mask multiplication. Saved masks reconstruct automatically; fine-tuning needs no external pruner object.

Pruning & fine-tuning

Validation, saved files, and resume

Pruning writes prune.pth, prune.config.json, and prune.validation.json. The report contains validation accuracy/loss, method, ratio/map, source, magnification, and input checkpoint. Compare candidate ratios using validation files; then fine-tune with validation-based selection. Do not choose settings through repeated test evaluations. Automatic ratio search is not implemented.

Fine-tuning passes the actual epoch and steps its supplied/configured scheduler. Best weights and last-epoch optimizer/scheduler/RNG state follow checkpoint rules, for both masked and channel-pruned models. Channel checkpoints save validated widths and retained indices. Parameter reduction does not establish measured latency gains; efficiency reports remain Stage 8 work.

Evaluation & efficiency

Classification definitions

  • accuracy is a percentage (0-100). Precision, recall, F1, sensitivity, specificity and sparsity use fractions (0-1).
  • Confusion-matrix rows are true labels and columns predicted labels. Ordered classes and class_to_idx are explicit: benign 0, malignant 1.
  • Per-class precision/recall/F1 and support are reported. Macro metrics give each declared class equal weight; weighted metrics use class support. Undefined divisions are zero, including absent classes. This convention can lower macro scores on a split containing only one class; support remains visible.
  • Binary sensitivity is malignant recall. Specificity is benign recall.
  • Loss is mean image cross-entropy, weighted by image count across uneven batches.

Evaluation & efficiency

Filename patient/slide metrics

Use manifest patient_id (YEAR-SLIDE_ID) as a grouping surrogate. Average softmax probabilities over each group's images and select the highest mean; ties select the first label. Each group then contributes one classification observation, regardless of image count. Reports preserve group probabilities, labels, image counts, and the same confusion/averaging conventions as image metrics.

These are filename-group metrics, not independently verified clinical patient metrics. all magnifications aggregate all selected images within the group. Mixed labels in a group, missing identifiers, dropped last batches, and shuffled manifest loaders are rejected. Generic datasets without row metadata report patient metrics as unavailable rather than inventing identities.

Evaluation & efficiency

Compute and latency protocol

Input dimensions come from the first real preprocessed evaluation image (normally 3 x 224 x 224), not a CIFAR-sized placeholder. Benchmark inputs repeat that image into a contiguous batch of --benchmark-batch-size, resident on the model device. The report records exact NCHW shape and dtype.

Hooks count Conv2d/Linear multiply-accumulates from actual forward outputs, including grouped convolution dimensions. This is explicitly a Conv2d/Linear compute estimate, excluding bias additions, BN, activation, pooling, residual adds and mask multiplication. The related FLOP estimate uses two FLOPs per MAC. Unstructured zeros do not reduce dense MACs. Channel removal changes dimensions and therefore changes this compute estimate.

After one untimed MAC-counting forward and the requested warm-up forwards, record repeated perf_counter_ns wall-clock forwards in inference/eval mode. CUDA synchronizes before and after each measured call. Timings include forward dispatch, pruning hooks and synchronization overhead. They exclude disk IO, transforms, host-to-device transfers, loss, and metric aggregation. Output-finite checks occur outside the measured interval.

Report mean, median, p95 (linear interpolation), min/max, population standard deviation, all samples, median-based throughput, and amortized per-image latency. Amortized latency is not single-image latency when batch size exceeds one. CPU threads, CPU identity/platform, GPU identity/memory/capability, PyTorch/Python, CUDA/cuDNN runtime, determinism and TF32 settings are recorded.

Keep hardware, dtype, batch size, thread counts, backend settings and protocol fixed. Close competing workloads and use adequate repeats for a real experiment. Cold-start initialization and end-to-end data-pipeline latency are not measured. Default timing runs are measurements, not a guarantee of statistical significance or reproducibility across different devices/drivers/software.

Evaluation & efficiency

Reading comparisons

relative_to_dense contains accuracy deltas in percentage points, actual file and model-state byte ratios, parameter/MAC ratios, observed median speedup, and signed latency change. Speedup is dense median / candidate median: below one is slower. Positive latency change means slower. Slowdowns and larger files are retained. Do not infer a practical speed benefit from mask sparsity or parameter reduction.

Verification covers hand-checked metrics/MAC counts, uneven-batch losses, filename group aggregation, mask-aware sizes, invalid settings/provenance, and no train/ validation iteration during comparisons. Existing real-v1 smoke checkpoints were compared for both masks and channel removal. Those small reports verify execution, not full-dataset accuracy or general hardware speedup claims.
