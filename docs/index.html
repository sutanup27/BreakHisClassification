User guide

BreaKHis classification and pruning

This project trains PyTorch models to classify breast histology images as benign or malignant, then evaluates, prunes, and fine-tunes the saved models. Model commands support binary classification. The eight-subtype dataset is audited, but multiclass training is not implemented yet.

First-run checklist

  1. Open PowerShell in D:\Sutanu_WorkSpace\BreakHis\BreakHisClassification.
  2. Activate .venv313 or use its Python executable directly. If starting from a fresh checkout, follow environment creation first.
  3. Check the interpreter, dependencies, binary images, and saved manifest:
powershell
python --version
python tools/check_environment.py --device cuda
Test-Path ../Dataset/dataset_cancer_v1/classificacao_binaria
Test-Path artifacts/data/manifest.json

Both Test-Path results must be True. Use --device cpu in the environment checker for a CPU installation. The checker runs a forward pass, not training. The dataset and manifest are local artifacts and are not included in Git. A fresh clone therefore needs those files copied into the layout below. If images moved, use --data-root while keeping their contents and manifest assignments unchanged.

Current setup limitation: after removing v2, the existing v1 manifest works, but the audit command cannot yet rebuild using v1 alone. Restore the existing manifest from your local backup; do not assume prepare-data works in a clean v1-only workspace. See prepare-data limitation.

  1. Run the tests before a long experiment:
powershell
python -m unittest discover -s tests -v
  1. Start with a separate one-epoch run to confirm the complete selected dataset loads and produces finite training/validation results:
powershell
python -m breakhis train --dataset breakhis --model vgg --magnification 40X --epochs 1 --batch-size 16 --num-workers 0 --experiment-id first-check

This still processes all selected training/validation images. It is not a small sample run. Expect train.config.json, train.pth, and train-last.pth in ../checkpoint/binary/40X/vgg/first-check/. Use a new ID if that directory already contains output files. A completed one-epoch run cannot resume for extra epochs; start a new baseline or fine-tune its weights.

User guide

Complete binary workflow

These commands use the existing saved manifest and the remaining v1 binary dataset. Keep the manifest, source, and magnification consistent throughout the experiment.

powershell
# Train and select the best weights using validation accuracy.
python -m breakhis train --dataset breakhis --source cancer_binary --magnification 40X --model vgg --epochs 20 --device auto --experiment-id baseline

# Prune weights and check validation performance.
python -m breakhis prune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --sparsity 0.5 --experiment-id baseline

# Fine-tune with the pruning masks still active.
python -m breakhis finetune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/prune.pth --epochs 5 --learning-rate 0.0001 --experiment-id baseline

# Evaluate the selected model on the reserved test split.
python -m breakhis evaluate --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/finetune.pth --output artifacts/final-test.json

Training and fine-tuning use the training split and choose weights using validation accuracy. Pruning reports validation performance. Evaluation uses the reserved test split; run it after choosing your model and pruning settings. Reported accuracy is a percentage on a 0-100 scale: 90.0 means 90%.

User guide

Train parameters

python -m breakhis train creates a new model unless --resume is supplied.

ParameterDefault / allowed valuesPurpose
--modelvgg; vgg, resnet, resnet18Architecture. resnet is an alias for torchvision ResNet18. The chosen name is used in the default checkpoint directory.
--epochs20; positive integerPasses through the training split. Validation runs after every epoch.
--learning-rate0.001Initial SGD learning rate. Use a positive value; for example 0.0001 for smaller updates.
--pretrainedOff; flagLoads torchvision pretrained ResNet18 weights, potentially downloading them. The binary classifier head is replaced. Has no effect for VGG, which does not load pretrained weights.

SGD uses momentum 0.9, weight decay 0.0005, and cosine learning-rate scheduling over the requested epochs. These settings are currently fixed in code. Weights are saved when validation accuracy improves. A new run refuses an existing checkpoint output. Choose a new experiment ID or output filename.

powershell
python -m breakhis train --dataset breakhis --model resnet18 --pretrained --epochs 10 --batch-size 16 --output resnet18-baseline.pth

This custom filename saves to ../checkpoint/binary/resnet18-baseline.pth.

User guide

Prune parameters

python -m breakhis prune loads weights, applies masks, checks validation, and saves weights. It performs no training.

ParameterDefault / allowed valuesPurpose
--checkpointRequired; file pathSupported checkpoint to prune. Architecture is reconstructed automatically.
--sparsity0.5; number from 0 to 1 inclusiveFraction selected for L1 unstructured pruning in each convolution and linear layer. 0.5 requests 50%; 0 requests none; 1 selects all. This does not remove channels or guarantee faster inference.

Masks are stored in the checkpoint and reconstructed on loading. Dense tensor shapes remain unchanged.

User guide

Fine-tune parameters

python -m breakhis finetune starts a new optimization run from saved weights. Pruned checkpoints retain their masks.

ParameterDefault / allowed valuesPurpose
--checkpointRequired for a new run; replaced by --resume when continuingStarting weights; architecture is read from the checkpoint. Do not supply --model.
--epochs20; positive integerAdditional training epochs. Set explicitly, for example --epochs 5.
--learning-rate0.001Initial rate for the new SGD optimizer. A smaller value can be useful for fine-tuning.

Uses the same optimizer, scheduler, and validation selection as training. Without --resume, optimizer, scheduler, and RNG state start a new run. With --resume, their saved states are restored.

Evaluate parameters

python -m breakhis evaluate evaluates saved weights on the test split.

ParameterDefault / allowed valuesPurpose
--checkpointRequired; file pathModel weights; architecture and pruning masks are reconstructed.
--outputExperiment-directory evaluate.jsonJSON report path. Example: --output artifacts/final-test.json. Parent folders are created. Evaluation saves no model weights.

User guide

Checkpoint paths and loading rules

CommandDefault output relative to the workspace parent
traincheckpoint/binary/<magnification>/<architecture>/<experiment-id>/train.pth
prunecheckpoint/binary/<magnification>/<architecture>/<experiment-id>/prune.pth
finetunecheckpoint/binary/<magnification>/<architecture>/<experiment-id>/finetune.pth

Defaults are resolved using the codebase location, independently of your working directory. For checkpoint commands, a bare output filename such as --output baseline.pth goes directly into checkpoint/binary/. An explicit relative or absolute path must resolve inside that task directory and end in .pth. From the codebase, --output ../checkpoint/binary/40X/vgg/baseline.pth is valid. Binary outputs cannot go into the multiclass directory. Checkpoint input paths can be anywhere.

Other explicit relative paths, including checkpoint inputs and evaluation reports, are relative to your current working directory. Quote paths containing spaces.

Each completed training/fine-tuning epoch also saves <name>-last.pth, including optimizer, scheduler, and random state. The main checkpoint remains the best validation model. Each command saves its resolved arguments as <name>.config.json; evaluation saves a JSON report automatically when no output is supplied.

Ctrl+C attempts to save partial-epoch weights as <name>-interrupted.pth. Resume from the completed-epoch -last.pth, not the partial weights. Work from an interrupted epoch is replayed. A second interruption or stalled operation can prevent saving.

Resume training and fine-tuning

ParameterCommandsPurpose
--resumetrain, finetuneCompleted-epoch checkpoint containing optimizer, scheduler, and RNG state. Cannot be combined with --checkpoint; training cannot combine it with --pretrained.
powershell
python -m breakhis train --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/train-last.pth
python -m breakhis finetune --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/finetune-last.pth

Omitted options inherit saved settings. --epochs is the original total planned epochs, not additional epochs on resume. Changing the planned total changes the cosine schedule and is rejected. Batch size, learning rate, worker count, deterministic mode, device, output, runtime versions, experiment ID, and dataset provenance must match. A fully completed run cannot be resumed for extra epochs; start finetune --checkpoint ... instead.

Exact epoch-boundary resume requires --num-workers 0. Background-worker RNG/prefetch states are not stored. The full original experiment directory, including its best checkpoint, must remain available. Reproducibility across different software/hardware or nondeterministic GPU operations is not guaranteed. Version-1 weights remain loadable for evaluation/pruning/fine-tuning, but do not contain exact resume state. See checkpoint format and resume.

Supported checkpoints contain architecture, binary labels, state dictionaries, epoch, and dataset metadata. Loading requires matching manifest hash, source, magnification, and preprocessing. Regenerating a manifest may invalidate checkpoint metadata. Old whole-model pickle files require explicit migration and are not automatically loaded.

User guide

Preprocessing and runtime

Images are converted to RGB and resized to a 256-pixel short edge with aspect ratio preserved. Training uses random 224 x 224 crops (padding 4) and horizontal flips. Validation/test use center crops. Tensors use ImageNet mean/std normalization. These are fixed in code; there is no image-size option. Older 460 x 700 evaluation accuracy is not directly comparable.

Each loaded image is checked against its manifest hash. Epoch logs show training and validation time, losses, and validation accuracy. --epochs 1 checks execution but still processes all selected images; there is no quick-subset argument. CPU execution and --magnification all can take longer. Measure throughput before increasing workers. Unstructured pruning does not automatically speed up dense computation.

Training and validation losses are averaged over samples, so a smaller final batch does not receive the same weight as a full batch. Invalid learning rates, epoch counts, and empty splits are rejected. Nonfinite inputs, outputs, losses, or gradient norms stop training; invalid gradients are rejected before the optimizer updates weights. This fail-fast validation can add device checks per batch.

Working on the codebase

The supported implementation lives in breakhis/. Root scripts and the historical Models/, DataProcess/, and Utills/ paths delegate to it. Edit the canonical module rather than adding another implementation to a compatibility wrapper.

To change behavior, locate the canonical module, implement the change, run the relevant existing tests, then run the suite above. Keep training/validation/test boundaries intact: model selection and pruning settings use validation, with the test split reserved for final reporting. Changes to preprocessing or split files must be reflected in checkpoint provenance so incompatible weights are rejected.

The supported pruning command currently applies L1 unstructured masks. Structured channel pruning helpers are experimental and need Stage 7 validation. Model commands do not currently support multiclass training, configurable image sizes, training-seed arguments, or quick-subset flags; avoid inventing CLI options.

Command reference

Supported commands

Use the existing patient manifest with the remaining v1 binary source; see DATASETS.md. Rebuilding currently requires the removed v2 source. The following supported pipeline uses a shared experiment ID:

powershell
python -m breakhis train --dataset breakhis --source cancer_binary --magnification 40X --model vgg --epochs 20 --experiment-id baseline

python -m breakhis prune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/train.pth --sparsity 0.5 --experiment-id baseline

python -m breakhis finetune --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/prune.pth --epochs 5 --experiment-id baseline

python -m breakhis evaluate --dataset breakhis --source cancer_binary --magnification 40X --checkpoint ../checkpoint/binary/40X/vgg/baseline/finetune.pth --experiment-id baseline

Supported baseline architectures are VGG and torchvision ResNet18 (resnet is an alias). ResNet pretrained weights download only when --pretrained is supplied. Other custom architectures remain experimental and are not CLI model choices.

The supported prune command uses PyTorch L1 unstructured weight pruning on convolution and linear layers. Masks are saved and reconstructed, and remain effective during fine-tuning. Structured channel pruning, architecture-specific pruning validation, and systematic ratio selection remain Stage 7 work.

Common options include --manifest, --source, --magnification, --data-root, --batch-size, --num-workers, --device, and --deterministic. Workers default to zero for simpler interruption handling on Windows. Use --num-workers 4 only after checking throughput on your machine.

Each improvement in validation accuracy saves the selected checkpoint. Ctrl+C also attempts to save partial weights to an -interrupted.pth file. Every completed epoch saves an independent -last.pth with optimizer, scheduler, and RNG state. Use --resume with that file; see CHECKPOINTS.md.

Dataset policy

Audited local sources

The audit decodes every supported image, checks filename metadata against its folder, computes SHA-256 hashes for the original file and decoded RGB pixels, and records the accepted images in a saved manifest. It does not edit dataset files.

No decoding failures were found in this local audit. Each source contains 125 repeated decoded images; the manifest excludes subsequent occurrences within that source. Cross-source entries are retained because source selection is explicit, and the sources are not concatenated for primary training.

The binary roots have 7,900 filenames in common, but none of those shared images have identical decoded pixels. dataset_cancer_v1 contains 224×224 versions; BreaKHis_v2 has mostly 700×460 images, with a smaller set at 700×456. The cancer dataset has nine additional named images. Their names and all changed content entries are saved in artifacts/data/audit.json.

Dataset policy

Identifier rule

The official BreaKHis dataset description documents procedure, tumor class, subtype, year, slide identifier, magnification, and sequence in the image filename. The grouping rule uses the full YEAR-SLIDE_ID:

text
SOB_B_A-14-22549AB-40-001.png
        └─ 14-22549AB is the patient/slide group

The subtype, magnification, and image sequence are excluded from the group key. Letter suffixes are preserved. The same identifier is grouped together even when it appears under more than one subtype. Local filenames yield 81 patient/slide groups; this is the local filename census, not an independently verified count of distinct people. No external patient-to-slide metadata is present in the repo.

Exact decoded-image duplicates also link groups before splitting, so matching content cannot appear in different splits. Conflicting binary labels within linked groups fail the audit rather than silently choosing a label.

Dataset policy

Split policy

The saved seed defaults to zero. Groups are stratified by binary label, shuffled with a local seeded generator, and allocated approximately 70% training, 15% validation, and 15% test by group count. Image proportions differ because patients have different numbers of images. Class/image distributions are reported for each source, magnification, and split.

All magnifications and all local source copies use consistent assignments for a patient/slide identifier. --magnification all therefore preserves group isolation. The audit validates zero patient overlap and zero exact decoded-content overlap across splits. It does not establish that visually similar, nonidentical images are unrelated; the filename identifier remains the patient-group reference.

Dataset policy

Prepare and reuse

From the repository directory, in the activated environment:

powershell
python -m breakhis prepare-data --seed 0

Outputs:

  • artifacts/data/manifest.json: source roots, seed, split fractions, patient-group rule, image paths, labels, magnifications, file/pixel hashes, and split assignments.
  • artifacts/data/audit.json: inventory results, exclusions, source comparison, dimensions, and class/patient distributions.

These generated files are ignored by Git. Keep the manifest with your experiment artifacts to reproduce its split. Rebuilding is deterministic for the same data and seed, but changed data creates a new experiment manifest.

powershell

Use --manifest for a different saved manifest. --data-root relocates the selected source without changing its split. The loader verifies each image's file hash against the audit while loading; altered files fail with an instruction to rebuild. Missing manifests fail clearly rather than falling back to image-level random splits.

Training and fine-tuning select weights using validation. The evaluate command alone reads the reserved test split for final metrics. Repeated use of test results to tune experiments would still compromise that independence.

The eight-class inventory is audited for comparison; primary commands remain binary. Its subtype field is preserved for a future eight-class extension.

All supported model commands normalize input paths and check manifest/checkpoint files and the selected dataset root before image loading or model construction. Experiment outputs

Without --output, model commands use:

text
checkpoint/binary/<magnification>/<architecture>/<experiment-id>/
  train.config.json
  train.pth                   # Best validation model
  train-last.pth              # Last completed epoch; resume state

Each invocation generates a UTC timestamp plus random suffix as its ID unless --experiment-id is supplied. Checkpoints & resume

Format version 2

Checkpoints use tensors and standard Python values, loaded with torch.load(..., weights_only=True). They do not pickle model instances.

FieldContents
format_version2; format 1 remains readable for weights-only workflows

state_dictCPU tensors, including weights, batch-normalization buffers, pruning originals and masks
metadataSource, magnification, preprocessing description/configuration, manifest hash/path, dataset root, and split-selection policy
epochCompleted epoch number; partial interrupted files use the last completed epoch number

Writes use a temporary sibling file and atomic replacement. Dense and supported unstructured models reconstruct from their declared architecture; mask hooks are reinstalled before loading state. Channel-pruned architecture reconstruction is not yet supported because structured pruning remains Stage 7 work.

Version 1 checkpoints can be evaluated, pruned, or used to start a new fine-tuning run. They cannot resume exactly. Legacy whole-model pickles are rejected rather than loaded with unrestricted unpickling. Missing fields, inconsistent labels, invalid format versions, and nonfinite weights are rejected.

Checkpoints & resume

Resume semantics

powershell
python -m breakhis train --dataset breakhis --experiment-id baseline --epochs 20 --num-workers 0 --deterministic
# If interrupted before the planned run completes:
python -m breakhis train --dataset breakhis --resume ../checkpoint/binary/40X/vgg/baseline/train-last.pth

Resume uses the same command (train or finetune) as the saved run. Omitted options inherit the saved effective settings. The scheduler is stepped before each completed-epoch checkpoint is saved. Restore starts at epoch + 1, with optimizer momentum, learning-rate schedule, best-validation tracking, Python RNG, NumPy RNG, PyTorch CPU RNG, CUDA RNGs, and recorded backend determinism settings. An epoch-zero last checkpoint allows restarting if the first epoch is interrupted.

The original planned epoch count and learning rate, batch size, worker count, deterministic mode, resolved device, output path, experiment ID, runtime versions, and dataset provenance must match. A changed total would define a different cosine schedule and is rejected. Completed runs require a new fine-tuning run rather than extending resume. Restore the original best checkpoint if it was moved; the experiment's best and last files belong together.

Exact resume is supported at completed-epoch boundaries with num-workers 0. Positive-worker runs still save optimizer/scheduler information but are marked nonresumable because worker RNGs and prefetch queues are not captured. Partial interrupted weights are nonresumable; restart from the last completed epoch and replay the partial work. Software/hardware changes and nondeterministic GPU kernels can change numerical results even when random states are restored.

Checkpoints & resume

Verification

Regression tests compare an uninterrupted stochastic CPU run with interrupted and resumed runs, for both dense and masked models. Final weights, optimizer, scheduler, and RNG states must match exactly. Separate actual VGG subprocess checks compare dense and pruned predictions using atol=1e-6, rtol=1e-5. GPU smoke checks validate actual checkpoint loading and finite inference; they do not establish full-dataset model quality or cross-device numerical equivalence.

Repair roadmap

Final acceptance run

  • PendingInstall dependencies into a fresh virtual environment.
  • PendingValidate the chosen dataset and saved patient splits.
  • PendingTrain one binary baseline and select its checkpoint using validation data.
  • PendingReload the baseline in a fresh process.
  • PendingPrune the baseline and verify its structural or mask invariants.
  • PendingFine-tune using validation selection and save/reload the result.
  • PendingEvaluate the selected baseline and pruned model on the reserved test data.
  • PendingGenerate the accuracy, size, computation, and latency comparison report.
  • PendingSave configuration, split references, checkpoint metadata, and logs.

Do not mark the codebase complete on syntax checks or a single successful import. Completion requires this reproducible end-to-end run and the relevant regression checks.
